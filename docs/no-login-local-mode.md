# ONEBIZ 2안: 완전 무인증 / 로컬 문서 모드

상태: 개발 분리 브랜치에서 설계. 기존 main, 운영 서버, 사용자 데이터 변경 없음.

## 제품 요구사항
- 카카오/네이버/구글 로그인 화면 및 일반 사용자 인증 요구 제거.
- 신규 사용자는 로그인 없이 견적서, 계약서, 고객정보, 대금관리 문서를 작성한다.
- 같은 단말에서 앱 데이터가 남아 있는 동안 과거 문서를 다시 조회·수정할 수 있다.
- 휴대폰 내부 앱 전용 저장소에 자료를 영속 저장한다 (테스트로 앱 종료/재시작/업데이트 확인).
- 민감 문서의 서버 동기화/공개 API는 제공하지 않는다. 신원 확인 없는 문서 서버 복구는 지원 불가.
- 기존 사용자 문서는 수정/삭제하지 않는다. 기존 서버 자료를 무인증 사용자에게 노출하지 않는다.
- 통합관리센터 관리자 로그인은 유지한다 (운영 보안상 필수). 일반 사용자 개인정보/문서 통계 기능은 새 모드에서 수집하지 않는다.
- 서버로는 개인식별정보 없는 집계 이벤트만 보낸다. 사용자별 또는 장기간 이용자 중복제거 수치는 제공하지 않는다.
- 알림톡·장비배차·전자서명 등 이용자 권한 확인이 필요한 서버 기능은 무인증 상태에서 그대로 동작시키지 않는다. 별도 승인/검증 절차 없이는 비활성화한다.

## 구현 순서
1. 실제 Android 앱 프로젝트 확보 후 데이터 저장 위치와 UI 내 로그인 진입점 파악
2. 신규 무인증 로컬 모드 플래그 및 첫 실행 데이터 초기화 설계
3. SQLite/Room 등 영속 저장, 백업 내보내기 및 가져오기(사용자 직접 관리, 암호화 권장)
4. 견적서/계약서/PDF 및 고객, 대금관리 저장·불러오기 회귀 테스트
5. 서버에 인증 없는 문서 CRUD 노출하지 않도록 API 분리/차단
6. 기존 데이터 마이그레이션은 소유권 확인 가능한 기존 계정 세션으로 일회성 내보내기한 뒤 별도 로컬 가져오기. 인증 제거 후 익명 복구 불가
7. 관리자/통계/SOLAPI 경로 테스트, 개인정보처리방침 및 Play Console 접근 안내 수정
8. 테스트 AAB 생성/검증 이후에만 신규 배포

## 출시 차단 기준
- 기존 설치 이용자의 자료 손실 위험
- 로컬 앱 삭제/초기화 후 복구 가능하다고 잘못 안내하는 경우
- 민감 문서에 인증 없이 접근 가능한 서버 엔드포인트
- 앱 프로젝트가 확보되지 않아 회귀 테스트가 불가능한 상태

## 확인된 서버 현황 (GitHub main 읽기 기준)
- server.js의 getSession()은 sessions 테이블과 users 상태를 확인한다.
- memberQuoteSendInfo(), memberPaymentDocument()은 snapshots의 user_id를 사용한다.
- subscriptionInfo(), hasEntitlement()은 사용자 식별을 전제로 한다.
- 따라서 server.js에서 인증 점검을 단순 삭제하는 수정은 금지한다.
